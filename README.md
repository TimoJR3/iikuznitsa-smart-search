# Умный поиск по каталогу store.softline.ru

Прототип для задачи «Умный поиск на сайте» хакатона ИИкузница (трек «Аналитик данных»). Поиск понимает смысл запроса, жаргон, опечатки и раскладку, различает «серверное оборудование» и «ПО для сервера», всегда отвечает минимум четырьмя товарами и предлагает сопутствующие решения. Команда магазина видит, что ищут клиенты и какие запросы остались без ответа.

## Что умеет

**Покупатель**
- Исправляет раскладку (`fcnhf kbyerc` → astra linux), опечатки и кириллическое написание брендов (`мдаемон` → MDaemon, `энидеск` → AnyDesk).
- Понимает жаргон и сокращения по словарю [`data/synonyms.json`](data/synonyms.json): «винда», «антивирь», «офис», «бесперебойник», «крипта про».
- Определяет намерение: «сервер» — оборудование, «по для сервера» — программное обеспечение.
- Гибридный поиск: слова (BM25) и смысл (эмбеддинги `multilingual-e5-small`), объединение рангов RRF. В ответе не меньше 4 товаров.
- Неуверенные запросы («программа для чертежей») переписывает GigaChat. Остальные обходятся без LLM и отвечают примерно за 0,14 с.
- Подсказки во время ввода: исправленный запрос, продолжения и товары.
- Допродажа: другие решения того же вендора, сопутствующие категории («ОС → защита, резервное копирование, офис»), аналоги других производителей, отметка акции по старой цене из фида.

**Команда магазина** (вкладка «Аналитика поиска»)
- Журнал каждого поиска: запрос, исправления, намерение, статус, уверенность, вызов LLM, первый товар, задержка, переходы в товар.
- Доля уверенных ответов и запросов без подходящего товара, частые запросы, категории спроса.
- Разбор запросов без уверенного ответа с разметкой причины: «Нет в каталоге», «Проблема поиска», «Недостаточно данных».

## Как устроено

```
YML-фид (136 040 SKU) ─► карточки продуктов в наличии (10 200) ─► индекс: BM25 + эмбеддинги
                                                                     │
запрос ─► нормализация, раскладка, транслит, опечатки, синонимы ─► намерение ─► гибридный отбор (RRF)
              │                                         уверенность < 0,5 ─► GigaChat переписывает запрос
              └─► подсказки при вводе                          │
                                                               ▼
                                   ≥4 товаров + допродажа + аналоги ─► журнал SQLite ─► аналитика
```

- `smartsearch/catalog.py` — разбор фида и сворачивание вариантов лицензий в карточки продуктов.
- `smartsearch/text.py` — нормализация, раскладка, транслитерация, стемминг.
- `smartsearch/index.py` — BM25 на разреженной матрице и эмбеддинги.
- `smartsearch/search.py` — понимание запроса, ранжирование, допродажа, подсказки.
- `smartsearch/llm.py` — GigaChat с кешем и журналом токенов `data/runtime/llm_usage.jsonl`.
- `smartsearch/analytics.py` — события и сводки.
- `app/` — FastAPI и страница демо.

API: `GET /api/search?q=`, `GET /api/suggest?q=`, `GET /api/analytics`, `POST /api/click`, `POST /api/gaps/label`, `GET /health`. Это точка подключения к витрине: сайт вызывает `/api/search` и `/api/suggest` и показывает ответ в своей вёрстке.

## Запуск локально

Данные задачи (фид и выборку запросов) положите в `data/raw/`: `Mindbox.yml.gz.xml`, `Выборка поисковых запросов.xlsx`. Скачать можно с папки организатора: `gdown --folder <ссылка из карточки задачи> -O data/raw`.

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
python scripts/build_index.py          # ~1–2 мин на CPU, скачивает модель эмбеддингов
python scripts/replay_queries.py       # выборка организатора в аналитику (source=replay)
uvicorn app.main:app --port 8000       # http://localhost:8000
python -m pytest -q
```

GigaChat необязателен. Чтобы включить, задайте `GIGACHAT_CREDENTIALS` и путь к корневому сертификату Минцифры в `GIGACHAT_CA_BUNDLE` (см. `.env.example`).

## Стенд

```bash
cp .env.example .env   # ключ GigaChat и SITE_ADDRESS=<ip>.sslip.io для HTTPS
docker compose up -d --build
```

Контейнер при первом старте собирает индекс в томе, Caddy выпускает сертификат Let's Encrypt. `restart: unless-stopped` поднимает стенд после перезагрузки ВМ.

## Ограничения

- В данных нет истории заказов, поэтому «часто покупают вместе» строится по правилам совместимости категорий и экосистеме вендора, а не по корзинам.
- Цен конкурентов в данных нет: показываем акцию по старой цене из фида. Сравнение с конкурентами требует внешнего источника цен.
- Ранжирование по маржинальности и популярности не реализовано: этих полей в фиде нет.
- Словарь жаргона составлен вручную по каталогу и примерам ТЗ. Пополнять его нужно из аналитики («Проблема поиска»).
